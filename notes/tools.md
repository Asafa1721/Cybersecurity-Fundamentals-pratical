# Notes: Cybersecurity Tools

Quick reference on the ten tools from Workbook 1, Module 06, with a realistic use scenario for each

| Tool | When it's used |
|------|-----------------|
| Kali Linux | Penetration testers boot into it for a full suite of assessment tools during an authorized engagement. |
| Wireshark | A SOC analyst inspects suspicious network traffic to see if data is leaving to an unfamiliar server. |
| Nmap | A pentester scans a target network at the start of an engagement to find live hosts and open ports. |
| Burp Suite | A web app tester intercepts and modifies HTTP requests to test for vulnerabilities like injection. |
| Metasploit | A pentester safely demonstrates that a found vulnerability is actually exploitable, for the client report. |
| Splunk | A SOC analyst searches logs to trace exactly when and how an account showed unusual login activity. |
| Microsoft Sentinel | A security team gets automatic alerts on things like a spike in failed cloud logins. |
| Nessus | An analyst scans company servers on a schedule to catch unpatched software before attackers do. |
| OpenVAS | A budget-conscious team uses it as a free alternative to Nessus for regular vulnerability scans. |
| VirusTotal | An analyst checks a suspicious attachment against dozens of antivirus engines before opening it. |

## Why this matters for the risk assessment
The tool recommendation in `final-project/risk-assessment.md` (Section 5) picks the tool that most directly reduces the highest-impact rows in the risk register — that's the reasoning recruiters want to see, not just a list of tool names.
